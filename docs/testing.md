# Testing Strategy

PropQuery is verified using `pytest`, targeting a local in-memory SQLite database (`sqlite:///:memory:`) to ensure fast, isolated execution of the test suite without affecting the PostgreSQL database.

## Test Environment Setup
Tests are configured in `tests/conftest.py`. The setup process:
1. Overrides the FastAPI `get_db` dependency to yield a session connected to the SQLite memory engine.
2. Creates all tables (`Base.metadata.create_all()`) before yielding the DB session.
3. Drops all tables (`Base.metadata.drop_all()`) during teardown.
4. Generates a valid JWT token via `create_access_token` and injects it into a `TestClient` instance to bypass the `get_current_user` dependency for authenticated API routes.

## Test Suites

### 1. API Route Tests (`tests/api/`)
Validates HTTP methods, schema validation, and database state.
- **Example**: `test_create_property`
  - Posts a JSON payload to `/api/v1/properties/` via the authenticated `TestClient`.
  - Asserts a `200 OK` response.
  - Queries the SQLite database directly to confirm the row was inserted correctly.

### 2. Service Logic Tests (`tests/services/`)
Validates pure business logic independent of the API routers.
- **Example**: `test_support_ticket_lifecycle`
  - Instantiates `SupportTicketService`.
  - Creates a ticket.
  - Transitions the ticket to `INVESTIGATING`.
  - Adds a manual note.
  - Transitions the ticket to `RESOLVED`.
  - Asserts that exactly 5 `SupportTicketUpdate` audit log entries were automatically generated by the service layer, verifying the strict enforcement of the audit trail.

## Running Tests
To run the test suite:
```bash
cd backend
pytest -v
```
